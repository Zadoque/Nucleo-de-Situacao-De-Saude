\section{Ponto de partida}
A Sprint 2 parte de uma Sprint 1 funcional. Já existe ingestão real do SINAN via PySUS, pipeline Bronze--Silver--Gold, persistência em Parquet, API FastAPI, Docker Compose e um protótipo de front-end. Portanto, a Sprint 2 não deve repetir a infraestrutura básica nem voltar a colocar downloads do SINAN dentro das requisições do dashboard.

\section{Objetivo}
Transformar o protótipo em uma primeira versão efetivamente geográfica do dashboard, permitindo navegar de Brasil/UF para municípios e consultar períodos de interesse com desempenho previsível.

\section{Atividade 1 -- Dimensão geográfica IBGE}
\begin{itemize}
\item Adquirir a malha territorial oficial do IBGE para UFs e municípios.
\item Manter o código IBGE de UF e município como chave de integração.
\item Criar uma dimensão territorial que forneça nome do município e geometria.
\item Validar que \texttt{ID\_MUNICIP} da Silver corresponde ao código municipal de sete dígitos usado pela malha.
\end{itemize}

Essa atividade resolve uma limitação deixada explicitamente na Sprint 1: \texttt{nm\_mun} não será preenchido por inferência ou por uma tabela informal, mas por uma fonte territorial oficial.

\section{Atividade 2 -- Mapa de calor}
\begin{itemize}
\item Substituir a tabela do protótipo por React ou outra solução adequada ao time.
\item Integrar Leaflet ou MapLibre.
\item Carregar GeoJSON das UFs.
\item Fazer join entre \texttt{cd\_uf} retornado pela API e a propriedade equivalente do GeoJSON.
\item Aplicar escala de intensidade baseada em \texttt{cases\_total}.
\item Mostrar doença, período e quantidade no hover.
\item Permitir click em uma UF para carregar os municípios daquela UF.
\end{itemize}

\section{Atividade 3 -- Períodos}
A API atual trabalha com ano e mês. Na Sprint 2 devem ser adicionados filtros para:
\begin{itemize}
\item mês/ano;
\item intervalo \texttt{start\_date}/\texttt{end\_date};
\item últimos 30 dias.
\end{itemize}
A Gold deverá ser ajustada se necessário para permitir essas consultas sem obrigar a API a reler a Bronze ou a Silver.

\section{Atividade 4 -- Qualidade e testes}
\begin{itemize}
\item Testar transformação de datas e códigos.
\item Testar deduplicação da Silver.
\item Testar agregação da Gold.
\item Testar \texttt{/heatmap/uf} e \texttt{/heatmap/municipios} com dados controlados.
\item Testar comportamento quando uma doença/ano ainda não foi processada.
\item Adicionar testes de integração do Docker Compose.
\end{itemize}

\section{Atividade 5 -- Pipeline e operação}
\begin{itemize}
\item Adicionar comando documentado para processar múltiplos anos.
\item Avaliar um worker separado caso o volume de ingestão aumente.
\item Criar política de batches e retenção.
\item Registrar falhas de ingestão sem apagar o último batch válido.
\item Considerar execução agendada posteriormente, mas manter ingestão e API desacopladas.
\end{itemize}

\section{Atividade 6 -- API}
\begin{itemize}
\item Padronizar modelos de resposta com Pydantic.
\item Adicionar paginação quando a consulta municipal exigir.
\item Adicionar endpoint de metadados da fonte/processamento.
\item Avaliar DuckDB para consultas Parquet mais eficientes antes de introduzir um banco de dados.
\end{itemize}

\section{Critérios de aceitação}
A Sprint 2 será considerada concluída quando:
\begin{enumerate}
\item uma doença real processada pelo PySUS puder ser visualizada no mapa por UF;
\item uma UF puder ser selecionada e seus municípios carregados;
\item o código IBGE conectar dados epidemiológicos e geometria sem joins por nome;
\item os filtros de período funcionarem sem novo download do SINAN;
\item testes cobrirem as principais transformações e endpoints;
\item Windows, Linux e NixOS continuarem executando a mesma pipeline por Docker Compose.
\end{enumerate}

\section{Fora do escopo desta sprint}
Não faz parte da Sprint 2 introduzir PostGIS, autenticação de usuários, análise preditiva ou monitoramento em tempo real. Essas decisões devem aguardar a validação do fluxo Bronze--Silver--Gold e do dashboard geográfico.

\section{Resultado esperado}
Ao final, o fluxo deverá ser:
\begin{verbatim}
PySUS -> Bronze -> Silver -> Gold -> FastAPI -> mapa
                         ^
                         |
                 filtros/períodos
\end{verbatim}
A regra arquitetural permanece: o dashboard consulta dados previamente processados; ele não inicia downloads do SINAN.
